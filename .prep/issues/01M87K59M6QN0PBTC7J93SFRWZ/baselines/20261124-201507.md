The chord progression e2e test failed about half the time (history like 'F×3 IV'). Investigation (2026-11-24): captured the audio the strum worker receives in failing runs and replayed it through StrumListener natively: the extra onsets reproduce, and the captured signal has two clicks 10 ms apart (second-difference ~300x the median, broadband rise in 129/182 flux bins) where the detector fires. Chrome's fake capture device occasionally misaligns a 10 ms buffer; it happens with 44.1 kHz and 48 kHz test files alike. On clean input (synthetic progression at 44.1/48 kHz, any hop alignment) there is no extra onset. A level-rise gate on flux onsets was tried and rejected: it doesn't stop click onsets and drops fast strumming detection (0.3 s: 100% -> 86% in chord_stream_eval). Fix: the test ignores repeat counts, which it doesn't test; a Rust test pins that clean ringing chords never start new strums.
